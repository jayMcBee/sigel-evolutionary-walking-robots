# Baseline for check.sh's `gui behaviour' section -- PORTING.md, step C10.
#
# THE VALUES ARE THE PORT'S OWN, for experiments/twoBases.exp,
# so a failure here means the port moved against itself. The behaviours below
# marked as compared with 1.3 match the running 1.3 binary, read through the
# sigel-x86 oracle driving the 2003 i386 build with XTest on
# twoBasesSimpleFitness2.exp, an experiment no longer shipped. Compared:
#   - the Fitness sort order, ascending on one click, INCLUDING the tie order
#     of equal-fitness rows
#   - the Add dialog's shape, except its maximum: 9999 here, 999 on 1.3, by
#     decision 2026-09-22 (item 58); and the five individuals it creates:
#     names from the file's NEXTIDENTIFIER up, fitness -1, age 0, sorting to
#     the TOP of a fitness-ascending list because -1 is below every real value
#   - the deletion confirmation's title, body, and Yes-as-default
#   - THAT THE APPLICATION SURVIVES deleting most of the pool. It did not:
#     Qt 6's QTreeWidget::clear() emits itemSelectionChanged() where Qt 2's
#     QListView::clear() blocked its own signals, and the stale item drove
#     1.3's getIndividual() into exit(1).
#
# WHICH LINES GUARD THAT REGRESSION. Whether the stale index is out of range
# depends on which row is current. On twoBases.exp it is: reverting the fix
# makes this scenario exit 1 at the deletion, so the section fails before any
# diff. Where the index stays in range, the signal repoints the detail pane at
# a SURVIVING individual instead and `nameIsASurvivor=0' flips to 1. SURVIVED
# is a liveness check only.
#   - that the detail pane keeps the DELETED individual's values afterwards
#     rather than blanking: 1.3 only calls individualView->clear() when the
#     list becomes empty, and the oracle read a non-survivor's name and a
#     populated history off the running binary. nameIsASurvivor=0 is the point.
#   - the TWO different context menus, and that the empty-space one clears the
#     selection. A click near the bottom of a FULL list still lands on a row,
#     so `itemAt(empty)=null' is part of the baseline: without it this section
#     silently tests the row menu twice.
#   - the MetaGP warning's three custom buttons. "Save && Remove" is the Qt 6
#     escape that renders the literal ampersand 1.3 showed; unescaped, Qt 6
#     eats it and underlines the space instead.
#
# Every scenario here is compared with SIGEL 1.3 EXCEPT four, which have no
# 1.3 side and say so here:
#   roundtrip   export, import, export on ONE machine. It needs no 1.3
#               reference and has none; it checks the port against itself.
#   metadrive   MT_GUI's toolbar actions. Pressed here, never pressed on 1.3,
#               so this is coverage on one side and not an agreement.
#   openfocus   the port's own crash. 1.3 made the tree item non-selectable and
#               never had the fault, so there is nothing to compare.
#   rngseed     the randomiser DOES agree with 1.3 -- PORTING.md, section 10 --
#               but this scenario's own lines are the port's measurement.
#
# QTEST IS NOT A MOUSE, and it applies to every section below. QTest posts
# QMouseEvent, QKeyEvent and QContextMenuEvent through QApplication::notify, so
# hit-testing, key handling, item-view selection and the slots behind them all
# run -- but it bypasses QWindowSystemInterface, so activation, grabs and
# double-click synthesis are not what a real click produces. The oracle's side
# was driven by real XTest, so every comparison with 1.3 has a genuine click on
# one end.
#
# ---------------------------------------------------------------------------
# From here on: PORTING.md step C11, the five View pages C10 never opened.
#
# C10 drove ONE of the six View pages. The other five hold every spin box,
# slider, combo, checkbox and validator in the application, and C7 had
# converted 21 validators that nothing on either side had ever typed into.
#
# WHAT HAS AN ORACLE READING BEHIND IT, and what does not, stated per block
# rather than in general, because the two are not the same strength:
#
#   VALIDATOR BATTERY -- confirmed against the running 1.3 binary, all twelve
#     probes, character for character, by the sigel-x86 oracle driving the
#     2003 i386 build with XTest. Both the double field and the integer field.
#     1.3 accepts the exponent "1e3", takes a leading minus in the INTEGER
#     field, turns "1.2.3" into "1.23" and "9,81" into "981" -- the comma
#     rejected as a keystroke, leaving a gap. The port does all four the same.
#
#   comma probes on the other validated fields -- four of them spot-checked on
#     1.3 (Planar spring constant, Level, Step Size, Maximal Error), all
#     "9,81" -> "981". The rest are the port's own measurement.
#
#   LOCALE INDEPENDENCE -- check.sh re-runs this whole scenario under
#     LANG=de_DE.UTF-8 and requires it to be IDENTICAL. That is not a Qt 6
#     nicety: the oracle built a de_DE with WOODY'S OWN localedef, verified it
#     with woody's own locale binary, ran the 2003 binary under it and got the
#     same seven results. So 1.3 is locale-independent as measured, and the
#     port matches. Reverting C7's locale pinning breaks it loudly -- "9.81"
#     becomes UNACCEPTABLE and "9,81" becomes accepted text that
#     QString::toDouble() reads back as ZERO, straight into the saved file.
#
#   spin boxes, sliders, combos, checkboxes, the two interlocks -- the port's
#     own driven measurement. Deterministic across runs and across three
#     locales, all measured. Where a 1.3 reading exists it is noted above.
#
# THE TWO INTERLOCKS ARE THE PART WORTH READING. Neither is visible without
# driving. The genetic sliders are not independent: Mutation + Crossover is
# clamped at 1000 and Reproduction is the recomputed remainder, so 200 Up on
# Mutation takes it 50 -> 250 and drops Reproduction 280 -> 80 with the sum
# staying exactly 1000; 200 Up on Crossover then stops at 750 rather than
# reaching 870. And sliderAlpha starts DISABLED -- the texture checkbox owns
# it -- so the generic probe measures a slider that cannot move, which is
# correct and says nothing; it is driven for real after the checkbox.
#
# ---------------------------------------------------------------------------
#
# ---------------------------------------------------------------------------
# From here on: PORTING.md step C11b, the Import/Export round trips.
#
# C10 drove ONE of the sixteen Import/Export children. These are FILE FORMATS,
# so the comparison is bytes -- the one kind of check i386-x87 against
# aarch64-IEEE cannot muddy, which is why this item was ordered ahead of the
# dialogs.
#
# SEVEN OF THE EIGHT EXPORTS MATCH THE 2003 i386 BINARY BYTE FOR BYTE. The
# sigel-x86 oracle drove the same eight exports on 1.3 with XTest on
# twoBasesSimpleFitness2.exp, with the same individual selected, and compared
# sha256, byte count, LF count, CR count and the trailing byte. The checksums
# below are the port's own for twoBases.exp.
#
#   .gpp .sip .env .pop .prg .ind .dat   identical
#   .lap                                 differs, and the reason is below
#
# The .dat is the one worth pausing on: on that file, 532 lines of floating-point output --
# generation, best, worst, average -- byte-identical across the two
# architectures. That was NOT expected and is a stronger result than the
# parameter files, which are text.
#
# .pop and .ind do NOT end with a newline. Measured on both sides.
#
# WHY .lap DIFFERS, and why the port is not the one that is wrong. 1.3 held the
# commands in a QDict and wrote them with a QDictIterator, so it emits them in
# HASH order; Phase D replaced that with an ordered QList, so the port emits
# the order the file supplied. Loading twoBasesSimpleFitness2.exp and exporting
# straight back, 1.3 returns a DIFFERENT order from the one it read: eight of
# the thirteen commands move, in three pairs and one triple -- because
# Q2Dict::insert prepends and re-inserting in iteration order reverses every
# colliding chain. The port preserves what it read. That
# is Phase D's documented consequence, not a C11b defect: "once the shim goes,
# load and save become order-preserving".
#
# OVERWRITE, D35. SIGEL's own "File exists..." prompt is gone, and the file
# dialog's confirmation is the only one. Three cases, each over a sentinel file:
#   no extension typed   checkEnding() adds .sip, finds that file taken and
#                        writes x11b-ow-<date stamp>.sip. Nothing asks, and the
#                        sentinel survives.
#   extension, No        the dialog's own confirmation asks, as a child of the
#                        dialog. The dialog stays open and is rejected, and the
#                        sentinel survives.
#   extension, Yes       the same confirmation; the file is written.
# 1.3 asked, and then wrote the file whatever the answer.
#
# ---------------------------------------------------------------------------
#
# ---------------------------------------------------------------------------
# From here on: PORTING.md step C11c, the six dialogs.
#
# THE LOAD-BEARING LINES ARE THE TWO `typing' ONES. Qt 6's QLineEdit selects
# its text when a dialog hands it focus down the tab chain; Qt 2's did not, and
# SIGEL only calls setText() then setFocus(), so a typed digit would REPLACE the
# pre-filled value where 1.3 appends to it:
#
#     Edit Command duration  0.01 + "5"  ->  0.015
#     Add individuals number 1    + "2"  ->  12
#
# Both figures are the oracle's, read off the running 2003 binary. The second is
# the one that costs: adding TWELVE individuals where two were meant leaves
# nothing wrong-looking behind, where a wrong duration at least shows. Four
# dialogs clear the selection with a QUEUED end(false) -- queued because the
# selection does not exist until exec() shows the dialog, and end() rather than
# deselect() because deselect leaves the cursor at position 0, which makes
# 1 + "2" read 21 rather than 12.
#
# Rename is deliberately NOT in that set: it calls selectAll() explicitly
# (SIG_ExperimentListView.cpp, slotRenameExperiment) and the oracle measured it
# pre-selecting in
# BOTH versions back in C10. Two of its readings eight steps apart, explained
# by three lines of code.
#
# C7's TWENTY-FIRST VALIDATOR is here, on SIG_EditCommandDialog -- the one
# C11a could not reach. Its seven probes match the other twenty and match 1.3.
# That closes the set at 21 of 21.
#
# A DIVERGENCE KEPT ON PURPOSE, recorded here so it is not mistaken for a
# regression: allowing a disallowed command calls addCommand(), which APPENDS
# to Phase D's ordered list, where Qt 2's QDict inserted at a hash position.
# Predicted before asking and confirmed on the binary character for character:
# 1.3 puts JMP SIXTH, straight after LOAD. Matching it would mean
# reimplementing Q2Dict, which is what Phase D removed -- see PORTING.md C11c.
# The written order after allowing JMP is in this baseline; it ends in JMP.
#
# WHAT ELSE THE ORACLE CONFIRMED: every title and label, OK carrying the
# default border on all four button dialogs, radio exclusivity, the Edit Host
# slave directory populated, Enable host checked (calibrated twice), both spin
# ranges, the Robot Information text and that its HTML is rendered rather than
# shown as tags, and that IndividualView is non-modal, has no buttons and
# ignores Escape -- which it is because SIG_IndividualViewBase derives from
# QWidget, not QDialog.
#
# ---------------------------------------------------------------------------
#
# ---------------------------------------------------------------------------
# From here on: PORTING.md, MT_GUI -- the MetaGP window.
#
# Reached by MetaGP > Use MetaGP, then MetaGP > Configure System. Nothing had
# ever opened it on either side. It is application-modal -- the oracle proved
# that with a control rather than a null: with the window open, a click on the
# main window's tree changed 0 pixels; with it closed, the identical click at
# the same coordinates changed 4397.
#
# THE LOAD-BEARING LINES ARE THE `locale=[C] numberOptions=2' ONES AND THE
# `group' PROBES. C7 pinned SIGEL_MasterGUI's 21 validators to QLocale::c()
# with RejectGroupSeparator; MT_GUI has ten more and NONE of them had been.
# It does not need a foreign locale to bite -- measured directly against Qt 6:
#
#     unpinned QIntValidator(0,1000), locale en_US, group separator ','
#         validate("1,000") = ACCEPTABLE
#         "1,000".toInt()   = 0, ok=false
#
# A user types one thousand, the field says it is fine, and ZERO reaches the
# system. Under de_DE the same happens with "1.000". Before the fix, 138 lines
# of this scenario changed under de_DE; now it is byte-identical, and the
# `group' probes read [1000] with toInt=1000.
#
# 1.3 REJECTS BOTH SEPARATORS -- read off the running binary, typing into the
# SWT field one character at a time: "1,000", "1.000" and "1000" all leave the
# field reading 1000. So this is a RESTORATION of Qt 2 behaviour, not an
# improvement on it. Qt 2 forced LC_NUMERIC="C" process-wide.
#
# The fix is applied at BOTH creation sites in MT_AddConstantsWidget: the type
# radio deletes and rebuilds its validators, so pinning them only in the
# constructor would be undone the first time a user switches between integer
# and float constants.
#
# THE CONSTANTS LIST IS NOT PINNED, DELIBERATELY. MT_IndividualsWidget
# generates its 30 constants with a randomizer at construction, so the values
# differ every run -- two runs of this scenario differed by exactly those 60
# lines and nothing else. What is invariant is the count and that every one
# parses as an integer in range, and that is what is checked instead.
#
# TREE LABEL TO SOURCE CLASS, because they do not match and both sides needed
# the mapping: Strategy = MT_EstimationWidget, Individual = MT_IndividualsWidget,
# Population = MT_PopulationWidget, GP Parameter = MT_SearchWidget,
# Selection = MT_SelectionWidget, Statistics = MT_StatisticsWidget.
# MT_ExperimentWidget is not a page at all -- it is the tree on the left.
#
# ---------------------------------------------------------------------------
#
# WHY THE MetaGP WINDOW IS 680x654. MT_MainWindow asks for resize(680, 595) and
# does not get it on either version: the oracle measured 1.3 opening at 680x605
# with a WM_NORMAL_HINTS minimum of 625x605, so Qt 2 already overrode the resize
# to satisfy its own layout. 1.3 cannot be dragged shorter than it opens, and at
# its own 605 the Statistics page is clipped -- group border and frame border
# both cut -- becoming complete at 654. The port honours the layout minimum over
# the resize call, which is 1.3's behaviour; matching 595 would reproduce
# neither its size nor its behaviour. PORTING.md, "The MetaGP window grew 59 px".
